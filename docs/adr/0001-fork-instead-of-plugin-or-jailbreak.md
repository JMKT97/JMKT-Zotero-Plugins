# Fork zotero-ios instead of building a plugin or a jailbreak tweak

Zotero's iOS app has no plugin or extension API of any kind — unlike desktop Zotero 6/7, which has a real JS plugin system, the iOS app is closed to runtime extension (confirmed against `github.com/zotero/zotero-ios`, which is a plain Swift/UIKit app, not a plugin host). A jailbreak tweak hooking the app's own binary was considered and rejected: no precedent tweak exists, it would need to be built from scratch against a closed native app, and it would break on every Zotero update and require the iPad to stay jailbroken indefinitely.

Instead, the Fork is a personally-built, personally-maintained modified copy of `zotero-ios`'s own source (AGPLv3-licensed, which restricts distribution/network-service use but not private on-device builds). This is viable because the app's PDF-open behavior is a single contained method (`DetailCoordinator.swift`, `show(attachment:...)` → `showPdf(at:)`), attachments are plain files at predictable paths rather than a proprietary container, and the sync client authenticates with the user's own API key rather than an app-embedded secret — so a self-built Fork can still fully replace the reader while remaining a real Zotero client.

# Build and distribute the Fork without a Mac or a paid Apple Developer account

The user owns no Apple hardware besides the iPad itself, and has ruled out paying for an Apple Developer Program membership ($99/year) to sign a personal single-device app. Both constraints are treated as fixed, not as trade-offs to revisit — building an iOS app normally assumes both a local Mac (for Xcode) and, for anything longer-lived than a 7-day free-signed app, a paid account.

The resolved pipeline: keep the Fork's repository **public** on GitHub, which makes its GitHub Actions macOS runner minutes free and effectively unmetered (private repos pay a 10x minute multiplier for macOS runners; public repos don't). The CI Builder compiles the `.ipa` there. SideStore (not AltStore/AltServer, which require an ongoing Mac/Windows companion) then free-signs and serves that `.ipa`, refreshing it on-device over Wi-Fi indefinitely past the 7-day free-signing expiry — a companion computer (the Pairing Host) is needed only once, for initial pairing, and Linux-native tooling exists for that step (`SideServer-for-Linux`, `Altcon`).

Consequences: the Fork must stay public (ruling out ever making the patch private without redesigning the build pipeline), and free-tier signing limits apply regardless of automation — at most 3 apps installed at once and 10 unique app-IDs signed per rolling week, shared across everything the user sideloads this way, not just this project. It also remains unconfirmed whether SideStore auto-redownloads a newly built `.ipa` from a custom source or only re-signs the already-installed binary in place; this affects whether shipping a new build to the iPad is fully hands-off.
